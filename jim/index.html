5. How this page works under the hood

This isn't a static page someone manually edits. The flow:

  1. Overnight, an automated job runs each barrel's scan (EDGAR full-text 8-K search, NASDAQ pre-mkt API, federal contract feeds, the SOBR-anchored copycat window).
  2. A Python script (scripts/refresh_jim_briefing.py) takes the morning's outputs, the active briefing markdown, and the current portfolio CSV, and regenerates this HTML using a Jinja-style template.
  3. The script commits the new jim/index.html to this repo and pushes. GitHub Pages rebuilds in ~30 seconds.
  4. The brief is sent as the body of an email to Jim — full content, not a teaser. Arrives between 7:30–8:00 AM ET on trading days. This page is the archive.
  5. Jim replies to the email with ideas / questions. Mike reads every reply and folds them into the next morning's brief. No accounts to create, no portals to log into.

The architecture is intentional. Briefings live as markdown in a private workspace; only the cleaned, public-safe narrative gets published here. No portfolio dollar amounts beyond what's in the document above, no account numbers, no PII.
